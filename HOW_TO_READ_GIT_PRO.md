If you are learning Git to start tracking your own code or collaborate with a team, you can skip over half the book. Pro Git is a reference guide, so you don't need to read it cover-to-cover.
Here is exactly what chapters you should read and skip to save time:

📖 Chapters You MUST Read
Chapter 1: Getting Started – Crucial for installing Git and understanding how it thinks about data.
Chapter 2: Git Basics – Covers 90% of your daily workflow (add, commit, status, log).
Chapter 3: Git Branching – The most important chapter. Git’s biggest strength is branching, and you need to master this.
Chapter 6: GitHub (or Chapter 5 in some sub-versions) – Essential if you plan to share your code or work with others on GitHub.



⏭️ Chapters You Can SKIP (For Now)

Chapter Number & Title	Why You Can Skip It
Chapter 4: Git on the Server	Skip unless you plan to host your own Git server on a private machine. Most people just use GitHub or GitLab.
Chapter 5: Distributed Git	Deals with complex open-source project maintenance and advanced patch emails. Skip for everyday development.
Chapter 7: Git Tools	Contains niche, advanced tools (bisect, submodules, rewriting history). Return to this later as a reference guide.
Chapter 8: Customizing Git	Covers writing your own automation scripts (hooks) and custom configurations. Not needed for beginners.
Chapter 9: Git and Other Systems	Explains how to move from old, obsolete systems like Subversion (SVN) or Perforce to Git.
Chapter 10: Git Internals	Deep dive into plumbing commands and exactly how Git stores binary data. Only read this if you want to write tools that interact with Git.
By focusing only on Chapters 1, 2, 3, and 6, you will cut your reading down from 450+ pages to roughly 130 pages and know everything required to be highly effective.
